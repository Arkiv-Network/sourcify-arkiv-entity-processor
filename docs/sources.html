Evidence behind these pages

This documentation belongs to the offline entity processor. Implementation statements describe the v3 stripped/shared payload format in this checkout; they do not describe an application server. The links below pin the v3 implementation used to generate this example. Its provenance additionally records Rust source digests and the binary hash. Capture and verified hydration equality are recorded there.

Processor implementation

  • source/prepare.ts — selects current Ethereum matches and referenced export rows
  • source/records.ts — maps export values into processor records
  • src/lib.rs — builds entities, hashes, references and spill parts
  • src/main.rs — writes the seed bundle and dispatches CLI commands
  • tests/ — real-data fixture and regression checks
  • README.md — operating instructions and bundle format

Processor PR #1 records the provenance and nullable-data fixes.

Lossless storage and reading

  • src/split.rs — v3 stripped envelopes, shared content and local artifact references
  • src/hydrate.rs — reference validation and lossless JSON reconstruction
  • src/hydrate_cli.rs — reads actual seed wire entries, including gzip and blob parts

Upstream reference

  • Production database mapping — server 4.1.2, commit reported by /version on 9 October 2026; standard JSON and signature selectors.
  • Sourcify dataset documentation — export tables and update model.
  • Sourcify OpenAPI specification — comparison vocabulary for public fields, not a server implementation requirement.
  • Sourcify API documentation — explains the upstream representation.

Reading the examples

The walkthrough uses a captured full Sourcify response for SafeProxy and entities generated from that response by the processor. The capture and validation record and reproduction instructions accompany the downloadable data. The field mapping is based on processor code. The findings distinguish stored values from information that would need later derivation or a different data source.
