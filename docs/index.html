Same contract information. Stored as Arkiv entities.

The processor takes a saved Sourcify dataset and turns it into linked Arkiv entities. Our priority is preserving what those records mean.

Sourcify records a contract’s source code, compiler settings, bytecode and verification result. The verification entity keeps the complete input JSON. We also create reusable pieces, so contracts can share identical source files and bytecode.

What “entity parity” means

For each accepted input record, the decoded verified_contract payload preserves every JSON value at the same path. A missing value must remain missing; a change of storage format must not silently change its meaning.

The deliverable is a seed bundle for import into Arkiv. This repository does not provide an HTTP API server. Sourcify API field names appear only as a familiar vocabulary for comparing the data.

Current scope

The processor accepts Ethereum mainnet records (source chain ID 1). It reads a snapshot, not live blockchain state.

Full API inputs are preserved. The Parquet adapter reconstructs standard compiler JSON and reads exported signatures; original relational IDs become supplementary attributes. Live proxy resolution remains unavailable offline. Regenerate previous bundles for the complete-input payload format. Complete Parquet-to-API parity has not been established; the findings page lists known gaps.
