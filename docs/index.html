Same contract information. Stored as Arkiv entities.

The processor takes a saved Sourcify dataset and turns it into linked Arkiv entities. Our priority is preserving what those records mean.

Sourcify records a contract’s source code, compiler settings, bytecode and verification result. We split that information into reusable pieces, so contracts can share identical source files and bytecode.

What “entity parity” means

For a contract in the imported snapshot, we should be able to trace each supported Sourcify value to the entity that stores it. A missing value must remain missing; a change of storage format must not silently change its meaning.

The deliverable is a seed bundle for import into Arkiv. This repository does not provide an HTTP API server. Sourcify API field names appear only as a familiar vocabulary for comparing the data.

Current scope

The processor accepts Ethereum mainnet records (source chain ID 1). It reads a snapshot, not live blockchain state.

Processor PR #1 retained original Sourcify IDs and fixed nullable data handling. Previously generated bundles need regeneration to contain those changes. Full parity has not been established; the findings page lists known gaps.
