# Supported Sourcify HTTP compatibility

This service implements `GET /v2/contract/1/{address}` against the configured
Arkiv dataset. It is a Mainnet read service, not a complete Sourcify server.
All-chains lookup, listing/pagination, verification writes and other chains are
outside its contract. Requests never fall back to a local bundle, Parquet files
or the Sourcify API. Live proxy resolution uses a configured Mainnet Ethereum RPC.

## Field contract

Minimal responses contain seven fields: `match`, `creationMatch`, `runtimeMatch`,
`chainId`, `address`, `verifiedAt`, `matchId`. The following seventeen fields are
optional, giving **24 supported fields**:

`abi`, `compilation`, `deployment`, `creationBytecode`, `runtimeBytecode`,
`sources`, `metadata`, `storageLayout`, `transientStorageLayout`, `userdoc`,
`devdoc`, `sourceIds`, `stdJsonInput`, `stdJsonOutput`, `additionalInput`,
`signatures`, `proxyResolution`.

| Request | Behavior |
| --- | --- |
| No query | Seven minimal fields |
| `fields=abi,compilation` | Minimal fields plus requested values |
| `fields=all` | All 24 fields, including live `proxyResolution` |
| `omit=abi,sources` | Supported fields except those optional top-level fields |
| `omit=proxyResolution` | The 23 stored/derived fields, with no live proxy work |
| `fields=proxyResolution` | Minimal fields plus a live result or nested proxy error |
| `fields` and `omit` together | 400 `invalid_parameter` |
| Unknown, empty or repeated query parameters | 400 `invalid_parameter` |
| Repeated selectors in one list | Deduplicated |
| `fields=all,abi` | 400 `invalid_parameter` |
| `fields=address`, `fields=chainId`, `fields=match` | 400; these fields are implicit upstream |

One level of dotted selection is accepted for these groups:

| Group | Selectable subfields |
| --- | --- |
| `creationBytecode` | `onchainBytecode`, `recompiledBytecode`, `sourceMap`, `linkReferences`, `cborAuxdata`, `transformations`, `transformationValues` |
| `runtimeBytecode` | All creation-bytecode subfields plus `immutableReferences` |
| `deployment` | `transactionHash`, `blockNumber`, `transactionIndex`, `deployer` |
| `compilation` | `language`, `compiler`, `compilerVersion`, `compilerSettings`, `name`, `fullyQualifiedName` |
| `signatures` | `function`, `event`, `error` |
| `proxyResolution` | `onchainRuntimeBytecode`, `onchainCreationBytecode` (raw stored values) |

Dotted `omit` selectors are validated but **do not remove subfields**. This
surprising behavior is present in the pinned production source and confirmed by
`omit_top.json` and `omit_nested.json`: both responses retain the complete
`deployment` object. The regression intentionally matches production behavior.
Required fields also survive `omit`, as confirmed by `omit_required.json`.

Selected top-level dependency closures are hydrated and validated. A nested
selection reads its containing stored field; it does not pretend to support
partial decompression of that field. Signatures require ABI instead of stored
signatures. Metadata requires compilation language. Absent fields remain absent;
nulls, empty arrays/objects and scalar JSON types remain distinct. For non-Solidity
compilations, existing metadata is returned as null, matching the reference.

When `stdJsonOutput` is selected, the server removes insignificant JSON whitespace
only from string values at `stdJsonOutput.contracts.*.*.metadata`. It validates the
embedded JSON, then filters whitespace outside quoted strings without parsing and
reserializing values. Quoted content, escape sequences, number spellings, key order,
nulls and absence remain intact; other strings and offline reconstruction are
unchanged. Invalid embedded JSON fails as corrupt data only when output is selected.

The independent SafeProxy response pair under
`crates/server/tests/fixtures/metadata-whitespace/` proves exact string equality
after this projection, including requests for `stdJsonOutput` alone. Upstream
[stores metadata as PostgreSQL `json`](https://github.com/argotorg/sourcify/blob/6048af7dfb36a3f5b7b2b30ede5daca3e701f7b0/services/database/migrations/20260826100000_add_compiled_contracts_metadata.sql)
and the pinned output selector casts it to text. Therefore this observed compact
representation is a serving policy, not a claim that every historical upstream
text can be recovered: an export may already have changed formatting, escapes or
key order, and original raw text is unavailable to this server.

## Live proxy resolution

The [pinned Sourcify proxy helper](https://github.com/argotorg/sourcify/blob/6048af7dfb36a3f5b7b2b30ede5daca3e701f7b0/services/server/src/server/services/utils/proxy-contract-util.ts)
uses **@shazow/whatsabi 0.29.0**. The Rust port preserves its bytecode heuristics,
resolver ordering, factory suppression and supported output types: `EIP1167Proxy`,
`EIP1967Proxy`, `GnosisSafeProxy`, `DiamondProxy`, `PROXIABLEProxy`,
`ZeppelinOSProxy`, `MaticProxy`, `SequenceWalletProxy` and `LivepeerManagerProxy`.
Detection examines stored creation bytecode when nonempty, otherwise stored
runtime bytecode. It does not fetch current Ethereum code. The fixed-address
heuristic is returned only for the upstream exact EIP-1167 prefix. These are
versioned heuristics, not proof that every possible proxy will be recognized.

Only selecting the exact top-level `proxyResolution` triggers live resolution.
`fields=all` and `omit` requests retaining this field also trigger it. Raw nested
selectors return the corresponding stored on-chain bytecode without Ethereum
calls; `proxyResolution.isProxy` and other result-property selectors are invalid.
Selecting both the top level and a raw subfield returns the live object regardless
of selector order. Dotted omit retains the same upstream quirk as other groups,
so it does not suppress live resolution. Imported historical proxy results are
never used as a substitute for live resolution.

The successful shape is `{isProxy, proxyType, implementations}`. Non-proxies use
`false`, `null`, and `[]`. Implementation addresses are checksummed; each name is
read from `compilation.name` in the same pinned Arkiv view as the original contract.
A missing verified implementation or empty name omits the `name` property. Facet
order, duplicates and zero addresses are preserved. Names therefore reflect the
local imported dataset, which can differ from a newer Sourcify database.

Without Ethereum configuration, or when detection/name lookup fails, the selected
field is `{proxyResolutionError: {customCode: "proxy_resolution_error", message:
"Error while running proxy detection and implementation resolution", errorId}}`,
with a fresh UUIDv4 and HTTP 200. A request-wide deadline still returns 504.
The upstream Diamond resolver catches ordinary remote/ABI failures and falls
through to other candidates, potentially yielding a non-proxy result. This quirk
is preserved. Adapter integrity failures (wrong chain, malformed RPC envelopes or
hex, changed views), local timeouts and resource limits instead fail resolution,
even when caught by that fallback. Beacon selector fallback is restricted to
execution reverts. RPC URLs and provider details never enter response errors.

Ethereum storage/call reads use one pinned EIP-1898 block hash with canonicality
required and a final block-hash check. The [runbook](server.md) documents the
separate global RPC gate, request cancellation and bounded response/work limits.

`crates/server/tests/fixtures/proxy/references.json` retains nine independent
responses captured on 2026-10-13 from the self-hosted official Sourcify service at
`https://sourcify-mirror.arkiv-global.net`: six detection examples, nested selectors
and a full SafeProxy response. These are test evidence only. The fixture README
pins the npm distribution integrity and independent 67-vector detector generator;
scripted resolvers and actual HTTP RPC mocks cover fallbacks and failure paths.

## Signatures are a serving policy

Stored/imported signatures are unchanged. Responses derive function, event and
error signatures from compiler JSON ABI, following the pinned Sourcify extraction
algorithm: canonical parameter types, tuple/array recursion, Keccak-256, full
32-byte hashes and first-four-byte selectors. Invalid fragments such as unresolved
library types are skipped. Constructors, fallback and receive entries are ignored;
anonymous events remain events. Duplicate signatures are collapsed per kind and
arrays are sorted by signature, matching the reference SQL's explicit ordering.
A null ABI yields three empty groups; a missing or malformed ABI needed for a
signature response fails rather than silently using stored signature tables.

`signature-vectors.json` was generated independently with **ethers 6.17.0**, the
version pinned by the deployed Sourcify lockfile. Its fixture generator exercises
aliases, overloads, tuples, nested arrays, anonymous events, errors, duplicates and
invalid input/output types. These vectors and the live `signatures.json` capture
are tested in Rust. The implementation covers compiler JSON ABI; it does not claim
to implement the complete Ethers human-readable ABI grammar.

Historical signature tables can differ from ABI-derived output, even if all
other stored fields match. That is a disclosed serving-policy distinction, not
snapshot corruption and not proof of universal current Sourcify data parity.
Live captures and independent retained-source comparisons must report any such
difference explicitly.

## Status, addresses and headers

Valid lowercase and uppercase addresses are accepted and returned in EIP-55
checksum form; mixed-case addresses must already have a valid checksum. The
lookup key is lowercase. Deployment `deployer` strings are also checksummed.
Path shape failures and selector failures use the reference's 400 error messages
covered by retained captures.

A missing contract returns 404 with exactly `match: null`, `creationMatch: null`,
`runtimeMatch: null`, `chainId: "1"`, and the checksummed `address`. It does not
return an error envelope, `matchId` or `verifiedAt`. This indicates absence from
the selected Arkiv dataset, not an assertion that Sourcify has never verified it.

Validation errors use the flat `{customCode, message, errorId}` envelope, with a
fresh UUIDv4. Tests compare status, code, message and UUID shape; random IDs are
not expected to match captured IDs. Arkiv transport, consistency, dependency,
capacity and deadline failures have explicit service-specific codes and 5xx
statuses in that envelope. They never masquerade as a missing contract.

JSON responses use `application/json; charset=utf-8` and wildcard CORS for browser
reads. Compression negotiates gzip and zstd. Infrastructure headers, Express's
`X-Powered-By`, Google's tracing/transport headers, ETags, JSON object-key order,
compressed bytes and random error IDs are not identity claims. The service uses
`Cache-Control: no-store` for its response policy. HEAD and write methods remain
outside the supported GET endpoint contract. Malformed percent-encoding is
rejected locally; undefined JavaScript object-property selector quirks are not
part of the supported field grammar.

`cargo test -p arkiv-sourcify-server --test parity` runs the captured and derived
compatibility regressions. Backend protocol, cancellation and HTTP routing tests
are separate. Passing these bounded cases does not claim complete Sourcify API
parity or complete coverage of the upstream dataset.
