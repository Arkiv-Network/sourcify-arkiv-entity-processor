What we preserve, and where parity stops

Entity parity is a data comparison. A successful import alone does not prove that every Sourcify field is represented.

Full input preservation

Hydrating the v3 verification envelope with its shared dependencies equals the complete processor input as JSON. API records retain all supplied fields, nested structures and unknown extra fields. The stored stripped envelope has a schema marker and explicit references; those storage fields are absent from the hydrated record. This does not recover fields omitted before processing.

Database adapter coverage

  • No internal IDs: records carry Sourcify API fields only. The database's compilation, deployment, verification and contract row IDs only join rows while preparing; the processor refuses input envelopes that carry anything beside the record. matchId is the API field.
  • Nullable data: null ABI stays null, missing Solidity metadata stays null, and source-map values retain their available form.

These changes are in processor PR #1. Existing bundles are not updated in place; regenerate them to include the enriched payloads. The v3 reference format changes verification and compilation keys; readers must support hydration. Whole-dataset storage savings have not been measured. Do not reuse old processed bundles.

Known limits

FindingConsequence
Snapshot scopeNew or changed upstream records require another export/import. There is no continuous synchronization.
Ethereum mainnet onlyPreparation selects source chain 1; transformation rejects other source chains. Destination Arkiv chain configuration does not add cross-chain source coverage.
Missing referencesThe source stream aborts on missing required dependencies unless --skip-missing-references is enabled, with skips capped by --max-skipped. The Compose pipeline enables bounded skipping by default. Skipped records are reported; missing metadata alone no longer causes a skip.
Signature table coverageBoth exported signature tables are required. Missing referenced signature rows fail reconstruction; they are never silently replaced with ABI-derived signatures. The small test fixture includes clearly identified synthetic signature rows, not full-corpus coverage. Signature groups are ordered by signature text, following the pinned production selector.
No live proxy resolutionThe database adapter supplies no current proxy resolution. Missing or empty resolution data remains unknown; no isProxy:false attribute is fabricated.
Bytecode null versus emptyRaw API inputs preserve null and 0x distinctly. The database adapter follows Sourcify’s SQL rule and maps empty bytecode to null. Supplementary shared code references also collapse empty code to null.
Compiler-output fidelityAPI input preserves every supplied compiler-output field. The database adapter reconstructs the selected artifacts exposed by Sourcify’s stdJsonOutput, not arbitrary original compiler output or ASTs. This is also how Sourcify constructs its response. Top-level non-Solidity metadata follows the service’s null rule; stdJsonOutput metadata retains the stored text.
Timestamp precisionThe database adapter formats verification timestamps to UTC seconds, matching Sourcify’s production SQL selector. This is not preservation of the database timestamp’s fractional precision.
Export versus API metadata textThe real SafeProxy export and saved API response differ in whitespace inside stdJsonOutput metadata, a JSON string. Parsed metadata values match, but the strings do not. The adapter retains the exported text exactly, as Sourcify’s SQL cast requires; the regression test exposes this exception explicitly.
Original bytes versus JSON valuesSource text is retained as content. Parsed and serialized metadata preserves represented values, not necessarily original whitespace, property order or an original IPFS artifact’s bytes.
Compilation hash definitionsThe v3 compilation content hash covers its complete canonical envelope before spill; it differs from source hashes, bytecode Keccak hashes and entity keys. See hashes and storage.

What the evidence establishes

Processor tests cover nullable ABI and artifacts, original IDs, staging identity, chunking and deterministic output. The fixture compares a small set of real export rows and labeled synthetic signature rows with expected records and decoded bundles. Standard JSON reconstruction is also compared with the saved API response. The real SafeProxy record matches every saved field except live proxyResolution. This is evidence for that fixture, not complete cross-source equality. Fresh work directories are required for source manifest v3 (prepared from PostgreSQL); sources prepared from Parquet are refused. This is not a live comparison of every field in every Sourcify contract.

The contract example compares the complete captured API response with its full hydrated JSON, alongside the actual stripped stored payload. It does not establish complete database-to-API parity.
